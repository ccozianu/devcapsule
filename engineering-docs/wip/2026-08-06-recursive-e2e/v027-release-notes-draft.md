# v027 Release Notes — Draft

Status: draft maintained during v027 preparation; becomes the release text
when the tag is cut. `R-COMPAT-001` requires the changed surface to be named
here; the mnemonic jump from v026.2 (no v026.3) deliberately marks the
command-line shape boundary.

## The changed command surface

v027 carries the significantly changed CLI shape settled in
`engineering-docs/design-notes/devcapsule/v1-user-experience.md` on
2026-08-23/24.

**New behavior**

- `devcapsule project init` now leaves a project fully initialized and
  runnable by its owner: it authors (or honors) the manifest, derives the
  platform lock offline from the client's embedded resolution matrix, records
  the owner's checkout answers, and ends with a fresh resolution. `init`
  followed by `run` is the entire owner first-run. Repairing a partially
  initialized project is `init`'s own job; a fully initialized project fails
  loudly and names `--regenerate`.
- Every configuration mutation is `VERB NAME VALUE` with one canonical node
  name: `config set NAME VALUE`, `config bind NAME PROVIDER:VALUE`
  (`host-directory:PATH`, `host-environment:VARIABLE`),
  `config authorize NAME VALUE [JUSTIFICATION]`, and the new
  `config unset NAME`. `init` and `run` accept the same spellings through
  repeatable `--set/--bind/--authorize` options; `run`'s answers apply to one
  launch and are never persisted.
- `project run [RUN-OPTIONS] -- DOCKER-RUN-OPTIONS` hands everything after
  `--` verbatim to `docker run`, conspicuously reported as a deviation from
  the resolved plan. The same passthrough exists on `run-image`.
- `host-browser`, `docker-daemon`, and `development-sudo` are authorization
  nodes available on every project; `host-browser` is persistable for the
  first time (`config authorize host-browser true`). Denial remains the
  default and a project recommendation remains advice.
- Interactive prompting (`ssh-keygen` style) asks only what no flag, record,
  or derivable default already answers; noninteractive runs fail once,
  listing every missing answer with its exact command-line remedy.

**Removed**

- `devcapsule project lock` — the dogfood stub could not author a V1 lock;
  `init` owns lock generation and `init --regenerate` regenerates it. Locks
  the stub already wrote remain fully readable.
- The bespoke `run` flags `--docker-daemon`, `--development-sudo`, and
  `--host-browser`; their persistent form is `config authorize`, their
  run-once form is `run --authorize NAME VALUE`, and raw docker needs go
  after `--`. (`run-image`, which reads no lock, keeps its dedicated flags.)
- The `config bind` provider options `--host-directory` and
  `--host-environment-variable`, replaced by the `PROVIDER:VALUE` spelling.

**Changed presentation**

- The CLI now parses with a stdlib-argparse framework instead of Click; help
  and usage text are formatted differently, and every CLI failure exits with
  code 2 (some legacy surfaces previously exited 1).

## Compatibility (`R-COMPAT-001`)

No user action is required for any project, checkout, or platform lock
created by a v026-series client. This is enforced by an automated fixture
(`tests/test_release_compatibility.py`) that runs the current client against
artifacts generated by the released v026.2 PEX and the v026-era hand-authored
adopter artifacts, verbatim, including the retired whole-manifest
`manifest-digest` field, which is deliberately ignored.

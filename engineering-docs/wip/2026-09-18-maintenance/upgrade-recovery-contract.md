# Upgrade recovery contract

Scope: the 2026-09-19 upgrade-recovery bug, selected by the owner on
2026-09-20. This is an implementation contract and verification map, not a
new configuration product design.

The subsequent owner-requested [full lifecycle contract](configuration-contract.md)
and [correctness audit](configuration-correctness.md) found additional failures
outside this repair's assessment boundary, including init consent provenance and
the lower launcher's treatment of denial. The invariants below describe this
repair's obligations; they are not a proof of the entire configuration pipeline.

## Ownership and execution

The trace starts at `cli.main`, through the command framework's project path
context, `commands.project`, `project_operations`, `project_configuration`,
the node registry, environment realization, and display/launch planning.

| Input or operation | Contract |
|---|---|
| Manifest | Project-authored identity, needs, ordinary value declarations and host recommendations. Recommendations grant nothing. |
| Platform lock | Project-authored exact components and formation inputs. A client upgrade does not replace it with the embedded matrix. |
| Checkout record | Developer-owned decisions addressed by canonical checkout path. Mutations preserve unrelated decisions, denials, bindings and state. |
| Generated resolution | Derived output. Source drift requires explicit resolution; resolution grants no consent and must not publish a partial plan. |
| Authorize | Validate a decision against the current declaration before recording it. `default` resolves now; it is never stored. Local base trust binds to an inspected immutable image ID. |
| Inspect | Show current answers, recommendations and pending decisions together, including in drift states. |
| Run | Validate configuration and run-once answers before materialization. No implicit configuration mutation or permission grant. |
| Display | Preserve explicit true/false decisions. Never infer renewed host-X11 consent from an earlier implicit default. Explain the selected transport and alternatives before building. |
| Materialization | Reuse only an exact verified formation; explain a required build before it happens. A changed launcher can legitimately change formation identity under D-0009. |

The accepted V1 split between explicit resolution and execution remains. The
broader matrix-update and obsolescence product design is outside this fix.

## Recovery invariants

1. Recovery is an assessment of current inputs, shared by inspection and
   resolution, not a second independently reconstructed validation policy.
2. Every offered authorization action is accepted by the same current value
   contract as `config authorize`. Local-image actions additionally require
   that the exact image still exists and passes inspection; no command can
   promise external availability.
3. A stale published base offers the current recommendation, never the old
   unreviewed digest. A local override remains visible and can be renewed by
   its recorded immutable identity without trusting a moved tag.
4. Stale grants and stale denials remain decisions. Recovery shows the old
   value, current recommendation and alternatives; it never turns a denial
   into a suggested mandatory grant.
5. Independent pending decisions are presented together. Refusal leaves the
   existing generated resolution and developer decisions unchanged.
6. Applying a selected offered action removes that pending decision without
   invalidating unrelated answers. After all required decisions, resolution
   succeeds and launch consumes the resulting choices.
7. Tool-only upgrade and project/lock changes are distinct cases. Historical
   inputs are retained as test evidence rather than regenerated by new code.

## Verification

The [unit case table](../../../devcapsule-src/tests/test_upgrade_recovery.py)
is supplemented by the [configuration ADT laws](../../../devcapsule-src/tests/configuration/test_adt.py). The historical inputs were produced by the released
v0.2.11 source, revision `94e798f1d1a7aaab93ae3e47d9636471448a8e66`;
their [provenance](../../../devcapsule-src/tests/resources/compat/README.md)
records the commands and the two path-dependent substitutions.

| Partition / obligation | Test evidence |
|---|---|
| Unchanged historical project, new client | ADT laws: predecessor needs no new decisions and resolution preserves its meaning. File-byte preservation is separately checked by `test_read_only_operations_preserve_configuration_files`; display behavior belongs to `test_display_decision_table`. |
| Manifest only / lock only / both changed × unanswered / true / false X11 | `test_upgrade_recovery_commands_converge_to_the_intended_launch`: real CLI refusals, listing, execution of offered commands, shrinking pending set, resolution and launch arguments. |
| Five host nodes × allow / deny × current / stale | `test_host_answer_state_table_and_executable_choices`: every offered alternative is executed and settles the node. |
| Missing / malformed / current / stale published and local bases | `test_base_state_table`, immutable-local recovery and unavailable-local refusal tests. No replay of a moved local tag or old published digest. |
| Every vendor acquisition × absent / allowed / denied / stale | `test_acquisition_decisions_use_the_same_review_contract`; repeated-init denial remains denied. |
| Independent validation errors, unknown nodes, state overlap | Review collects value/binding/secret/authorization/state errors; neither refusal nor failed local inspection replaces saved output. |
| Legacy / contained image × unanswered / true / false | `test_display_decision_table`; denied legacy X11 stops before building; valid choices feed the launch. |
| Run-once malformed / persistent-only / raw conflicting option | `test_invalid_run_once_choices_cannot_trigger_a_build`. |
| Removed current / legacy host decisions with stale output | The two `test_force_*` cases prevent resurrection through `--force`. |
| Unrelated values, bindings, adopted state, secret source names | `test_recovery_preserves_values_bindings_secrets_and_adopted_state`; secret values never enter output or records. |
| Regeneration preserves developer denial | `test_regeneration_preserves_an_existing_denial`; reading a recommendation is not an answer from the developer. |
| Required build explanation precedes the build | Existing materialization narrative test now asserts the explanation inside the build callback. |

The command journeys retain the real parser, project context, validators,
serialization, resolver and realization orchestration. Only external Docker,
image building and GUI launch are substituted. Assertions cover persisted
decisions and launch arguments, not just message substrings.

## Acceptance boundary

The incident's exact old manifest, lock, checkout record and intervening build
log were not supplied. Historical fixtures establish the client-only contract
and deterministic changed-input recovery; they cannot reconstruct those missing
facts. No actual Docker/GUI upgrade was performed here. The bug remains `fixed`,
not `closed`, until the owner validates the existing host checkout's recovery,
display choice and build explanation. Broader upgrade/matrix selection design
remains with project-management.
